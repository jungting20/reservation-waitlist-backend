# 요구사항

## 1. 문제 정의

사용자가 원하는 스터디룸과 1시간 시간대를 예약하고, 이미 예약된 경우 선착순 대기열에 등록할 수 있는 백엔드 서비스를 만든다. 예약이 취소되면 해당 시간대의 첫 번째 대기자를 즉시 예약자로 자동 승급한다.

## 2. 사용자 역할

### USER

- 활성 스터디룸과 예약 가능 시간대를 조회한다.
- 빈 시간대를 예약한다.
- 이미 예약된 시간대의 대기열에 등록한다.
- 자신의 예약과 대기 상태를 조회한다.
- 허용된 시간 안에 자신의 예약 또는 대기를 취소한다.

### ADMIN

- 스터디룸을 생성·수정·비활성화한다.
- 예약 가능 시간대를 관리한다.
- 필요하면 예약을 강제 취소하거나 변경한다.
- 사용자 취소 제한과 관계없이 운영 조치를 수행할 수 있다.
- 모든 운영 조치는 감사 가능한 이력으로 남긴다.

## 3. 기능 요구사항

1. 예약은 정확히 1시간 단위다.
2. 빈 방과 시간대에 대한 예약은 생성 즉시 `CONFIRMED`가 된다.
3. 같은 방과 시간대에는 활성 확정 예약이 최대 하나만 존재한다.
4. 한 사용자는 같은 시간에 여러 방을 예약할 수 없다.
5. 한 사용자는 같은 시간에 여러 방의 대기열에 동시에 등록할 수 없다.
6. 사용자는 예약 시작 10분 전까지 예약을 취소할 수 있다.
7. 관리자는 시간 제한 없이 예약을 강제 취소하거나 변경할 수 있다.
8. 예약된 방과 시간대에는 대기 신청을 할 수 있다.
9. 대기 순서는 대기 등록 시각 오름차순이며, 시각이 같으면 ID 오름차순으로 결정한다.
10. 예약 취소 시 첫 번째 `WAITING` 대기자는 별도의 수락 절차 없이 예약자로 자동 승급된다.
11. 취소된 예약과 대기 기록은 삭제하지 않고 이력으로 보존한다.
12. 모든 API 시간은 ISO 8601 형식을 사용한다.

## 4. 비기능 요구사항

- 서비스의 사용자 기준 시간대는 `Asia/Seoul`이다.
- DB에는 시간을 UTC로 저장한다.
- 예약과 대기열 승급은 트랜잭션으로 처리한다.
- 중복 예약 방지는 애플리케이션 검증뿐 아니라 DB 제약조건으로도 보장한다.
- 인증 실패와 권한 실패를 각각 401과 403으로 구분한다.
- 예약 충돌과 잘못된 상태 전이는 409로 응답한다.
- 관리자 강제 변경에는 행위자, 대상, 변경 전후 값과 시각을 기록한다.

## 5. 정상 흐름

### 정상 흐름 A: 즉시 예약

1. 사용자가 활성 방의 예약 가능 시간을 조회한다.
2. 비어 있는 1시간 시간대를 선택한다.
3. 서버가 충돌 여부를 확인한다.
4. `CONFIRMED` 예약을 생성한다.

### 정상 흐름 B: 대기 등록과 자동 승급

1. 사용자가 이미 예약된 방과 시간대에 대기를 신청한다.
2. 서버가 중복 예약·대기 여부를 확인한다.
3. `WAITING` 항목을 생성한다.
4. 기존 예약이 취소되면 가장 먼저 등록한 대기자를 선택한다.
5. 선택된 대기 항목을 `ACCEPTED`로 바꾸고 새 `CONFIRMED` 예약을 원자적으로 생성한다.

### 정상 흐름 C: 사용자 예약 취소

1. 사용자가 자신의 예약 취소를 요청한다.
2. 현재 시각이 예약 시작 10분 전보다 이른지 확인한다.
3. 예약을 `CANCELLED`로 바꾼다.
4. 대기자가 있으면 첫 번째 대기자를 자동 승급한다.

## 6. 실패 흐름

1. 사용자가 같은 시간에 다른 방을 이미 예약함 → 409.
2. 사용자가 같은 시간에 다른 방의 대기열에 이미 등록됨 → 409.
3. 예약 시작까지 10분 이하로 남은 상태에서 사용자가 취소함 → 409.
4. 비활성 방이나 과거 시간대를 예약함 → 422.
5. 다른 사용자의 예약을 조회하거나 취소함 → 403 또는 정보 노출 방지를 위한 404 정책 중 구현 전에 결정.
6. 이미 취소된 예약을 다시 취소함 → 409.
7. 빈 시간대에 대기 신청함 → 직접 예약하도록 409.
8. 동시 요청으로 같은 방과 시간대에 두 예약이 생성되려 함 → 한 건만 성공하고 나머지는 409.

## 7. 범위

### MVP 포함

- 이메일/비밀번호 인증
- USER/ADMIN 권한
- 스터디룸 관리
- 예약 가능 시간 조회
- 예약 생성·조회·취소
- 선착순 대기 등록·취소·자동 승급
- Swagger, 테스트, Docker 기반 로컬 실행

### 제외

- 결제, 소셜 로그인, 프론트엔드
- Kubernetes, 마이크로서비스
- 대기자 수락 제한시간과 `OFFERED` 만료 작업

## 8. 결정이 필요한 항목

- 관리자가 예약을 “변경”할 때 기존 예약을 수정할지, 취소 후 새 예약을 만들지
- 예약 시작 시각의 허용 범위(예: 매시 정각만 허용)
- 방별 운영 시간과 휴무일 정책
- 다른 사용자의 리소스 접근 시 403과 404 중 어떤 응답을 사용할지
